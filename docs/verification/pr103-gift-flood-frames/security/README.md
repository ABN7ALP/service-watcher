# البند 6-7 — ثغرة أمنية: إثبات بخادم حي فعلي

## الثغرة المُصلَحة

`socket.on('room-gift-support', { roomId, seatNumber, targetUserId, value })` كان يثق
بـ`value` القادمة من العميل مباشرة (حدّ أعلى 100,000 فقط، بلا أي خصم فعلي أو تحقّق من إرسال
هدية حقيقية) ويبثّها فوراً لكل المتصلين بالغرفة. أي مستخدم مسجَّل بإمكانه تزوير عداد الدعم
المعروض أسفل أي مقعد لأي قيمة، لأي مستخدم، بإطلاق هذا الحدث يدوياً من console المتصفح —
بلا حاجة لإرسال أي هدية حقيقية أو امتلاك أي رصيد.

## الإصلاح

حُذف المعالج بالكامل من `server/services/socketService.js`. عداد الدعم أسفل كل مقعد
(`room-support-updated`) يصل الآن حصراً من داخل `applyGiftToRoomSupport`
(`server/controllers/giftController.js`)، بعد الخصم الذري الحقيقي من رصيد المرسل مباشرة —
لا مسار socket منفصل يمكن استدعاؤه بمعزل عن الهدية الحقيقية بعد الآن.

## الفحص 1 — سكوني (الكود المصدري الحقيقي المُشغَّل بهذا الاختبار بالضبط)

```
hasVulnerableHandler: false
```

قراءة مباشرة لـ`server/services/socketService.js` (بعد إزالة سطور التعليق التي تُوثِّق
الحذف صراحة — لتفادي نتيجة إيجابية كاذبة من التوثيق نفسه) تؤكد غياب
`socket.on('room-gift-support'...)` تماماً من الكود الفعلي.

## الفحص 2 — ديناميكي (هجوم حقيقي، خادم حي)

1. خادم `server/server.js` حقيقي + `mongodb-memory-server` (replica set) + Playwright.
2. متفرّج حقيقي (متصفح Chromium) داخل الغرفة، بمقعد ضحية حقيقية مشغول فعلياً.
3. اتصال `socket.io` **خام** (لا متصفح) كمستخدم **مسجَّل وحقيقي** (أحد المرسلين المبذورين،
   بتوكن JWT صحيح تماماً) يُطلِق الحدث القديم المحذوف يدوياً:
   ```js
   socket.emit('room-gift-support', {
       roomId, seatNumber: 2, targetUserId: <الضحية>, value: 1000000
   });
   ```
4. انتظار 1.5 ثانية (أطول من أي نافذة دمج حقيقية بالنظام، 500ms) قبل القياس.

### النتيجة

| القياس | قبل الهجوم | بعد الهجوم |
|---|---|---|
| العداد المرئي أسفل مقعد الضحية (`.seat-support-row`) | `0` | `0` |
| `dataset.supportTotal` | `0` | `0` |

- **لم يتغيّر العداد المرئي إطلاقاً** — الهجوم بلا أي أثر.
- **القيمة المزوَّرة (1,000,000) لم تظهر بأي مكان بالـDOM** إطلاقاً.
- المعالج القديم لم يكن يُرسِل `ack` أصلاً أساساً — لا رد وصل لمحاولة الهجوم.

راجع `after-attack.png` (لقطة متفرّج فعلي بعد الهجوم مباشرة) و`results.json` للتفاصيل الكاملة.

**كلا الفحصين (السكوني والديناميكي) ناجحان.**
