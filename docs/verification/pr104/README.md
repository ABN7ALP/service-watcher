# PR #104 — صقل نهائي قبل الدمج: صورة افتراضية حقيقية + تموضع التاج/الشارات

ملاحظة مُلزمة من طلب المراجعة: **لم يُلمَس batching الهدايا، ولا مسح قطع اتصال المضيف، ولا
الإصلاح الأمني، ولا تغييرات `io.to`، ولا منطق توليد الإطارات/سرعة الحركة من الجولة السابقة —
كل هذا مُعتمَد مسبقاً ولم يتغيّر بهذه الجولة بتاتاً.**

## 1) الصورة الافتراضية المفقودة

**السبب**: `/images/default-avatar.png` لم يكن له ملف فعلي بـ`public/images/` إطلاقاً — كل
مقعد بلا `profileImage` (أو برابط صورة ميت) كان يعرض أيقونة صورة مكسورة + نصّ alt يفيض من
تحته، بالضبط كما ظهر بلقطات الجولة الثالثة.

**الإصلاح**:
- أصل جديد حقيقي: `public/images/default-avatar.webp` — ظلّ شخص محايد (رأس+كتفان) فوق خلفية
  رمادية داكنة مسطّحة، 256×256، **980 بايت فقط** (الحدّ المطلوب ≤20KB). مربّع لا دائري مسبقاً
  — القصّ (دائرة/مربّع دوري الزوايا) يأتي من CSS حسب السياق (`.avatar__photo` أو
  `.full-profile-avatar` وغيرها)، فيناسب كل الأشكال بلا تشوّه. معاينة:
  [`default-avatar-preview.png`](./default-avatar-preview.png).
- كل مرجع `/images/default-avatar.png` بالكود (13 موضعاً) حُوِّل لمرجع واحد
  `const DEFAULT_AVATAR_URL = '/images/default-avatar.webp'` بـ`app.js` — لا نصّ مكرَّر.
- 🐛 إصلاح جانبي اكتُشِف أثناء اختبار هذا البند تحديداً: 12 موضعاً آخر كانت تعتمد صورة
  افتراضية **خارجية** (`i.ibb.co`) — غير قابلة للوصول فعلياً ببيئة هذي الجلسة (تأكَّد بفشل
  تحميلها الفعلي أثناء الاختبار الحي أول مرة)، فتُعيد إدخال نفس علّة "صورة مكسورة" من مصدر
  مختلف تماماً. حُوِّلت كلها لنفس `DEFAULT_AVATAR_URL` المحلي الموثوق — لا اعتماد على أي CDN
  خارجي للصورة الافتراضية بعد اليوم بأي مكان بالتطبيق.
- `avatarHTML()` (مكوّن الأفاتار الموحَّد) يستخدم `DEFAULT_AVATAR_URL` مباشرة لو `src` فارغة.
- `<img class="avatar__frame">` (الإطار الزخرفي) كان بالفعل `alt="" aria-hidden="true"` منذ
  الجولة الثالثة — لا نصّ alt يمكن أن يظهر منه إطلاقاً (تحقَّق، لا تعديل لازم هنا).

### مستمع `onerror` عام وحيد (لا تكرار يدوي لكل `<img>`)

مستمع واحد `document.addEventListener('error', ..., true)` (**مرحلة الالتقاط إلزامية** —
أحداث خطأ `<img>` لا تصعد بمعيار DOM). النطاق: أي `<img class="avatar__photo">` (كل صور
`avatarHTML()` بأي مكان بالتطبيق) أو `<img data-avatar-fallback="1">` (صور أفاتار/غلاف خام
خارج `avatarHTML()` — فرق/مباريات PK، لوحة المتصدرين، معلومات الغرفة...، 18 موضعاً أُضيفت لها
الصفة). عند فشل التحميل: استبدال `src` بـ`DEFAULT_AVATAR_URL` **مرة واحدة فقط** (حارس مقارنة
`src` الحالية بالاحتياطي نفسه يمنع أي حلقة نظرياً).

### `dead-url-fallback/` — مقعد برابط صورة ميت عمداً + إطار حقيقي معاً

مقعد `dead-url-seat` بغرفة 19 مقعداً: `profileImage` مضبوطة يدوياً لرابط محلي غير موجود
(`/images/does-not-exist-123456.jpg`، 404 مضمون) **مع** إطار حقيقي مُفعَّل بنفس الوقت —
يثبت أن الاحتياطي يعمل حتى مع إطار. القياس الفعلي بعد الانتظار (`r4-results.json` →
`deadUrlSeat`):

```json
{ "src": ".../images/default-avatar.webp", "naturalWidth": 256, "complete": true }
```

**الصورة تحمّلت فعلياً بنجاح** (`naturalWidth=256`، لا 0) — لا أيقونة مكسورة، مطابق للقطة
[`r4-dead-url-seat.png`](./dead-url-fallback/r4-dead-url-seat.png).

### عدّاد `naturalWidth===0` — المقياس الحقيقي المطلوب

قياس حقيقي بعد انتظار اكتمال تحميل كل `<img>` (مرّتين متتاليتين — الثانية تلتقط أي استبدال
onerror حدث أثناء الانتظار الأول):

| الصفحة | مقاعد | إجمالي `<img>` | `naturalWidth===0` |
|---|---|---|---|
| غرفة 9 (`r4-room9-375.png`) | 9 | 29 | **0** |
| غرفة 19 (`r4-room19-375.png`) | 19 | 63 | **0** |

صفر صورة مكسورة على كلا الصفحتين — راجع [`r4-results.json`](./r4-results.json) للقيم الخام.

### `test-avatars-used/` — 19 صورة اختبار محلية حقيقية مختلفة

19 صورة أفاتار مولَّدة محلياً (وجوه مسطَّحة بتوليفات بشرة/شعر/خلفية متنوّعة — لا مربّعات لون
صلبة، "تبدو كصور حقيقية" بما يكفي لمقياس مقعد) خُدِمت مؤقتاً أثناء الاختبار الحي عبر
`public/_test-avatars/` (غير مُلتزَمة بـgit — سقالة اختبار فقط، حُذفت بعد الالتقاط، تماماً
كاستبدال CDN المؤقت بالمنهجية). كل مقعد بغرفتي 9/19 (عدا مقعد الرابط الميت عمداً) يحمل واحدة
منها فعلياً — راجع ورقة التلامس [`avatars-contact-sheet.png`](./test-avatars-used/avatars-contact-sheet.png).

## 2) تاج المضيف يتصادم مع حافة الإطار

**السبب**: `.voice-seat-host-badge` كانت مرساة بإزاحة (`top: calc(var(--hostAv) * -.3)`) من
حافة `.voice-seat-av-wrap` نفسها (حجم الحلقة/الصورة فقط)، لا من حافة صندوق الإطار الفعلي
(`--frame-box`، يتجاوز حافة الحلقة بنسبة أكبر بكثير منذ نموذج "البصمة الثابتة" بـPR السابق —
170/155/140% حسب الكثافة) — فيبدو التاج غارقاً داخل زخارف الإطار العلوية بدل الجلوس فوقها.

**الإصلاح**: نفس معادلة `--frame-box` المستخدَمة لحجم `.avatar__frame` نفسه — إزاحة
`(100% - var(--frame-box, 170%)) / 2` تُعطي بالضبط حافة صندوق الإطار العلوية (بصرف النظر عن
الكثافة، متغيّر واحد يتكفّل بالتوافق تلقائياً بلا أي قيمة خاصة بأي شبكة)، مع
`transform: translate(-50%, -90%)` (لا -100%) — يرفع التاج فوق الحافة بمعظمه مع تراكب مقصود
~10% من ارتفاعه، مطابق تماماً لطلب المراجعة.

### `host-crown-closeups/` — مضيف بلا إطار + مضيف بإطار الأدمن

- `r4-room9-host-closeup.png`: مضيف **بلا إطار** — التاج يجلس فوق الحلقة البسيطة بنظافة.
- `r4-room19-host-closeup.png`: مضيف **بإطار الأدمن** الحقيقي (التاج الذهبي بأسدين متقابلين) —
  التاج الآن فوق حافة الإطار بوضوح، تراكب خفيف مقصود فقط عند طرفه السفلي، لا غرق داخل الزخرفة.

## 3) شارة رقم المقعد والمايك فوق زخارف الإطار

**السبب**: نفس علّة التاج بالضبط — `.voice-seat-no` (أعلى-يمين) و`.voice-seat-mic-badge`
(أسفل-يسار) مرساتان بإزاحة صغيرة ثابتة (±0.15em) من حافة `.voice-seat-av-wrap` الصغيرة، لا
من حافة صندوق الإطار الأكبر — فتظهران "فوق" زخارف ذهبية كثيفة بدل زاوية نظيفة خارج الإطار.

**الإصلاح**: نفس معادلة `(100% - var(--frame-box, 170%)) / 2` (±0.15em إضافية للمس أنيق
لحافة الصندوق لا توضّعاً بمنتصف فراغ) — تعمل تلقائياً بكل الكثافات (9/13/19/80) بمتغيّر واحد،
بلا قيمة خاصة بأي شبكة. z-index رُفع صراحةً (5 للشارتين، 6 للتاج) فوق `.avatar__frame`
(z-index:2) — كانتا بالفعل أعلى رقمياً ضمن نفس سياق التكديس المشترك (لا `.voice-seat-av-wrap`
ولا `.avatar` يُنشئان سياق تكديس معزولاً)، فالتموضع الجديد هو الإصلاح الفعلي، لا الطبقة.

### `seat-badge-closeups/` — مقعد عادي بإطار، رقم المقعد + المايك بزاوية الصندوق الخارجية

`r4-room9-seat-closeup.png` و`r4-room19-seat-closeup.png`: رقم المقعد (أعلى-يمين) وأيقونة
المايك (أسفل-يسار) الآن عند الزاوية الخارجية لصندوق الإطار فعلياً — خارج الزخارف الذهبية
الكثيفة، بخلفية داكنة واضحة (موجودة أصلاً بالتصميم: `#1b1426`/`rgba(0,0,0,0.65)`) تبقيهما
مقروءتين فوق أي فنّ إطار بغض النظر عن ألوانه.

**الاتّساق عبر الكثافات**: المعادلة تعتمد فقط على `--frame-box` (متغيّر CSS سياقي موجود
أصلاً بكل كثافة — 170% عادةً، 155% بـ13/19 مقعداً، 140% بـ80 مقعداً)، فتتوافق تلقائياً بكل
الشبكات الأربع بلا أي قيمة إضافية مكتوبة لأي منها — مطابقاً نفس بنية الحل بالجولة السابقة.

## المنهجية

نفس أسلوب الجولات السابقة: خادم `server/server.js` الحقيقي كعملية Node متصلة بـ
`MongoMemoryReplSet` حقيقي، ومتصفح Chromium حقيقي (Playwright)، تسجيل دخول حقيقي عبر
`/api/auth/login`. مكتبات CDN المحجوبة بسياسة شبكة هذي الجلسة استُبدلت مؤقتاً بنسخها من سجل
npm مخدومة محلياً عبر `/vendor/*` أثناء هذا الاختبار فقط — `public/index.html` أُعيد بالكامل
لحالته الأصلية بعد الاختبار ولم يُدفع أي تعديل عليه.

## ما لم يُلمَس بهذي الجولة

- Batching الهدايا، مسح قطع اتصال المضيف، الإصلاح الأمني، تغييرات `io.to`.
- خوارزمية توليد/توقيت حركة الإطارات (`normalize-frames.js`/`check-frames.js`) من الجولة
  السابقة — الأصول نفسها لم تُعَد توليدها بهذي الجولة.

كل هذي معتمدة مسبقاً ولم تتغيّر بسطر واحد بهذي الجولة.
